# CQA: оценка качества диалогов операторов

Прототип для Freedom Broker (Data Challenge'26, команда **pavloral larpers**). Система читает диалог (чат или звонок), по чек-листу оценивает работу оператора и для каждого критерия показывает ответ, баллы, короткое объяснение и реплику-доказательство. Диалоги на русском, казахском и английском. Оценивается только оператор; реплики бота и системы это контекст.

## Как это устроено

- **Нейросеть отвечает по критериям с доказательствами.** Для каждого критерия модель сначала пишет объяснение, потом номер реплики и дословную цитату, и только потом ответ (да / нет / N/A или ступень шкалы). Ответ строго по JSON-схеме; цитаты проверяются по тексту диалога.
- **Итог считает код, а не модель.** `src/cqa/scoring.py`: N/A исключается, вес перераспределяется, округление половина вверх до 2 знаков. Грубая ошибка отмечается отдельным флагом. Покрыто тестами.
- **Чек-лист настраивается.** Критерии, веса, шкалы и уточняющие правила (rules) хранятся в JSON (`src/cqa/checklist.default.json` для чатов, `checklist.calls.json` для звонков) и меняются на сайте с версиями. Если поменяли только веса, ответы модели переиспользуются: пересчёт бесплатный и мгновенный.
- **Апелляции.** Проверяющий оспаривает ответ по критерию, принимает решение, итог пересчитывается; исходный ответ модели сохраняется.
- **Воспроизводимость.** Оценка кэшируется по тексту диалога, версии чек-листа и цепочке моделей: повторный запуск не платит и даёт тот же результат. Файл для организаторов всегда считается по стандартным чек-листам из репозитория. «↻ Переоценить» на сайте вызывает модель заново.

## Модели и ограничения

- **Основная модель:** Claude Sonnet 5.5 (облачный API), около $0.02 за диалог, оценка чата занимает 5–7 секунд. Запасные по порядку: Claude Opus 5.5, затем Gemini 3.5 Flash-Lite. Порядок задаётся в `EVAL_MODELS`; в файле результатов в поле `model.name` указаны модели, которые реально сработали.
- **Почему облачная модель:** нужно понимание русского, казахского и английского в одной оценке и дословные цитаты-доказательства; на 10 диалогов контроля это секунды и копейки.
- **Ограничения:** ответы модели на пограничных критериях (например, «Корректная и полная консультация») могут отличаться от оценки эксперта; поэтому у каждого ответа есть объяснение и цитата, а проверяющий может оспорить ответ на сайте. Звонки оцениваются по транскрипту. Если модель недоступна, диалог попадает в файл как запись со `status: error`, а не пропадает.

## Быстрый старт

Нужен Python 3.9 или новее и ключ хотя бы одной нейросети (Claude или Gemini).

```bash
git clone https://github.com/thelonelyslay/PavloLarpDataSci.git && cd PavloLarpDataSci
python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt                          # движок, сервер и сайт
cp .env.example .env                                     # затем откройте .env и впишите ключи
python3 src/cqa/fetch_data.py && python3 src/cqa/evaluator.py --id p1-ru-001
```

Последняя команда скачивает диалоги в `data/raw/dev.json` и печатает оценку одного диалога в JSON.

## Сервер и сайт

```bash
python3 -m uvicorn server.app:app --reload
```

Откройте http://127.0.0.1:8000/ — список диалогов, оценка с переходом к реплике, апелляции, редактор чек-листов, пакетная оценка и выгрузка результатов. Документация API: http://127.0.0.1:8000/docs. При старте сервер загружает диалоги из `data/raw/dev.json` (или по `DATA_API_URL`) в `data/server.sqlite3`.

Если порт 8000 занят, запустите на другом: `python3 -m uvicorn server.app:app --port 8011` и откройте http://127.0.0.1:8011/

Без файла `.env` и данных сайт откроется, но список диалогов будет пустым: нужен `DATA_API_URL` или файл `data/raw/dev.json`, а для оценки ещё и ключ модели.

## Тесты

```bash
(cd src/cqa && python3 -m unittest -v)          # движок: подсчёт, оценка, выгрузка, разметка
python3 -m unittest -v server.test_evaluations   # сервер: кэш, апелляции, веса, пакеты, выгрузка
```

Тесты не ходят в сеть и не вызывают настоящие модели.

## Выгрузка и проверка результатов

```bash
# DEV из готовых оценок (без оплаты); --expect-ok падает, если есть записи с ошибкой
python3 src/cqa/export_results.py --set dev --only-cached --validate --expect-ok
# дооценить недостающее (платно) и выгрузить
python3 src/cqa/export_results.py --set dev --workers 4 --validate --expect-ok
# проверить готовый файл по правилам организаторов
python3 src/cqa/validate_results.py results/dev/results.json --dialogs data/raw/dev.json --expect 65
```

С сайта то же самое: кнопка экспорта или `GET /api/export?set=dev` (по умолчанию только готовые оценки).

## Контрольный этап: 10 чатов за 5 минут

```bash
# 1. диалоги prod: по group_id из API (или положите файл организаторов в data/raw/prod.json)
python3 src/cqa/fetch_data.py --group-id <PROD_GROUP_ID> --out data/raw/prod.json
# 2. оценить, выгрузить и проверить (около 20 с и $0.2 на 10 чатов)
python3 src/cqa/export_results.py --set prod --from-file data/raw/prod.json --workers 4 --validate --expect-ok
# 3. убедиться: «ok 10, error 0», «оценок по моделям: claude-sonnet-5-5: 10», «нарушений нет»; затем
git add results/prod/results.json && git commit -m "results: prod" && git push
```

Если какой-то диалог дал ошибку, повторите шаг 2: готовые оценки берутся из кэша, заново оценится только упавший.

## Настройки .env

| Переменная | Зачем |
|---|---|
| `DATA_API_URL` | ссылка на API с диалогами (выдают организаторы) |
| `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` (+ `GEMINI_MODEL`) | ключи нейросетей |
| `EVAL_MODELS` | модели по очереди: первая основная, остальные запасные |
| `EVAL_TIMEOUT`, `EVAL_EFFORT` | предел времени на одну оценку (120 с) и глубина рассуждений Claude (low) |
| `TEAM_NAME`, `PROD_GROUP_ID` | имя команды в файле результатов; group_id prod для `/api/export?set=prod` |
| `MODEL_PRICES` | цены моделей, которых нет в коде |

## Где что лежит

- `src/cqa/evaluator.py`: оценка одного диалога, выбор модели, запасные модели.
- `src/cqa/scoring.py`: подсчёт баллов. `src/cqa/prompting.py`: задание для модели и проверка ответа.
- `src/cqa/export_results.py`, `validate_results.py`: файл результатов для организаторов и его проверка.
- `server/`: API (FastAPI) и база SQLite. `web/`: сайт на HTML/CSS/JS без сборки.
- `AGENTS.md`: договорённости команды и контракт API.

## Правила

- Ключи и ссылка на данные только в `.env`. Этот файл в Git не попадает.
- Диалоги и ответы API (`data/`) в Git не попадают.
- Файлы результатов для организаторов `results/<set>/results.json` хранятся в Git: в них ответы по критериям, обоснования и номера реплик, без текста диалогов.
