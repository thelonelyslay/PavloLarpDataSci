## 2. Роли
- **Рамазан (лид):** движок оценки (запросы к нейросети, проверка формата ответа), точность (лаборатория: разметка против системы), интеграция, выбор модели, решения по контракту.
- **Алихан:** сервер (FastAPI) и база (SQLite): данные, чек-листы с версиями, оценки, апелляции, решения; пакетная обработка с повторами и таймаутами; запуск по README; публичный Git.
- **Надир** (роль в 3 частях, он может взять не все):
  1. **Качество и разметка:** вручную размечает диалоги по чек-листу (эталон для проверки точности); проверяет казахские диалоги.
  2. **Интерфейс:** собирает страницы из макета с помощью бесплатного ИИ.
  3. **Демо и питч:** сценарий на 5 минут, запасное видео, README для жюри.

## 3. Что уточнили организаторы
- Чек-лист на 8 критериев сделан для чатов. Для звонков логика та же, но критерии 4 и 6 адаптируются к речи. Подготовлен `checklist.calls.json`.
- Задача шире 8 критериев: нужна **гибкая система**, где можно создавать и применять разные чек-листы (в том числе для звонков). Значит: несколько чек-листов, копирование, выбор по каналу (`applies_to`), версии.
- Справочник с эталонными ответами не выдаётся. Но есть **материалы по продуктам Freedom Broker**: запросить у организаторов, использовать как справку для критерия «Консультация».

## 4. Главные решения (сегодня до 14:00)
1. Модель для оценки: сравнение на 5 диалогах (точность, скорость, цена).
2. Контракт API (`AGENTS.md`): утвердить.
3. Чек-листы: `checklist.default.json` (чаты), `checklist.calls.json` (звонки). Редактор должен уметь создавать новые.

## 6. Что показать жюри (5 минут)
1 мин: интерфейс и диалог. 2 мин: оценка, обоснование, клик по реплике, пример N/A, итог. 1 мин: апелляция и решение. 1 мин: замена критерия и применение.
Бонусы (только после основного): уверенность модели и флаг «нужен человек», очередь проверки, история изменений, цена оценки, статистика по критериям.
