# CQA Freedom Broker — веб-интерфейс (`web/`)

Зона ответственности: **Надир** (ветка `nadir/web`, папка `web/`). Чистые HTML/CSS/JS без сборки, можно встроить в Dynamics 365.

## Откуда берутся данные

| Что | Источник |
|---|---|
| Диалоги, транскрипт, аудио | `GET /api/conversations`, `GET /api/conversations/{id}` |
| Чек-листы | `GET /api/checklists` (на сервере из `src/cqa/checklist.*.json` и сохранённых версий) |
| Оценка | кнопка **«▶ Оценить»** → `POST /api/evaluations {conversation_id, checklist_id}` |
| Итог, баллы, ответы, пояснения, модель, стоимость | только из JSON оценки (формат в AGENTS.md). В браузере ничего не пересчитывается и не подставляется |
| Апелляция | `POST /api/evaluations/{id}/appeals {criterion_id, comment}` |
| Решение проверяющего | `POST /api/appeals/{id}/decision {decision, new_answer?, reason}`, после него оценка перечитывается с сервера |
| Замена критерия | правка в черновике → **«Сохранить и применить»**: `POST /api/checklists` → `POST /api/checklists/{id}/activate` → `POST /api/evaluations/batch` |

**Демо-режим.** Если `GET /api/health` не отвечает, страница показывает `demo/demo_data.js` и жёлтый баннер **«ДЕМО-ДАННЫЕ»**. Там 6 синтетических диалогов, не из DEV. Ответы по критериям заданы вручную только для проверки интерфейса, итоги посчитаны `src/cqa/scoring.py` (`python3 web/demo/build_demo.py`). В демо-режиме оценка, апелляции и сохранение чек-листа отключены.

**Пороги отображения** (70 / 90 для раскраски итога, 85 % — целевой уровень по критерию) в задании не заданы. Это настройка («⚙ Пороги отображения» на вкладке аналитики): она только раскрашивает интерфейс и не влияет на баллы.

## Экраны

1. **Мониторинг диалогов.** Список с фильтрами (канал, язык, грубые ошибки, апелляции) и поиском. Транскрипт с номерами реплик `#message_index`. Карточка оценки:
   - итог (если изменён апелляцией, исходный зачёркнут), грубая ошибка, секции;
   - по каждому критерию: ответ, баллы, вес до и после перераспределения N/A, пояснение, правило (`rules`), цитаты-доказательства с переходом к реплике (у звонков ещё и к моменту записи), проверенный участок `checked_range`, причина N/A;
   - модель, стоимость и версия чек-листа.
2. **Апелляции.** Очередь обращений. Решение «подтвердить» или «изменить» с обязательной причиной; варианты ответа берутся из типа критерия (да/нет, ступени шкалы, N/A).
3. **Аналитика.** Средний итог, распределение по порогам (настройка), соблюдение по критериям, экспорт CSV/JSON.
4. **Чек-листы.** Редактор критерия: ID, название, секция, тип, вес, ступени шкалы, N/A и его условие, инструкция, **правила и уточнения (`rules`)**. Правки идут в черновик (хранится в браузере), на сервер — по кнопке «Сохранить и применить».

## Запуск

- **С сервером:** откройте `index.html?api=http://localhost:8000/api` или укажите адрес в окне статуса (справа сверху). Если страницу отдаёт сам сервер, `/api` берётся с того же адреса.
- **Без сервера:** откройте `web/index.html` двойным кликом — включится демо-режим.

## Вопросы к контракту (для Рамазана и Алихана)

- `GET /api/conversations` должен отдавать id последней оценки (`last_evaluation_id`). Пока его нет, UI пробует `GET /api/evaluations?conversation_id=…`.
- В `criteria[].appeal` нужен `id` апелляции для `/decision`. Пока его нет, UI ищет его через `GET /api/appeals?status=open` по `evaluation_id` и `criterion_id`.
- `POST /api/checklists` должен возвращать сохранённый чек-лист с `id`.
