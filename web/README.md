# CQA Freedom Broker — веб-интерфейс (`web/`)

Зона ответственности: **Надир** (ветка `nadir/web`, папка `web/`). Чистые HTML/CSS/JS без сборки, можно встроить в Dynamics 365.

## Запуск вместе с сервером

Сервер Алихана (ветка `Server_Alikhan`) отдаёт папку `web/` на `http://127.0.0.1:8000/`. Адрес API задан константой `API_BASE = '/api'` в `api.js` (относительный путь). Для разработки можно открыть `index.html?api=http://127.0.0.1:8000/api` или указать адрес в окне статуса (внизу слева).

## Откуда берутся данные

| Что | Маршрут |
|---|---|
| Диалоги | `GET /api/conversations`, `GET /api/conversations/{id}` |
| Чек-листы | `GET /api/checklists` → `GET /api/checklists/{id}` |
| Оценка одного диалога | «▶ Оценить» → `POST /api/evaluations {conversation_id[, checklist_id]}`. Без `checklist_id` сервер берёт активный чек-лист канала. Есть состояния «Оцениваем…» и «Ошибка оценки» (текст ошибки от сервера) |
| Оценить все | фоновая задача `POST /api/evaluations/batch/start`, прогресс через `GET /api/evaluations/batch/{job_id}` (переживает перезагрузку страницы) |
| Грубые ошибки | фильтр «⚠️ Нарушения»; под диалогом показано пояснение флаг-критерия от модели |
| Апелляция | «Оспорить оценку» → `POST /api/evaluations/{id}/appeals`; проверяющий во вкладке «Апелляции» видит обоснование, комментарий и фрагмент диалога, жмёт «Принять» (`decision: change`, `new_answer`) или «Отклонить» (`decision: confirm`) → `POST /api/appeals/{id}/decision`, итог пересчитывает сервер |
| Чек-лист | правки в черновик → «Сохранить версию» (`POST /api/checklists` + `/activate`) → «Применить к диалогам и пересчитать» (`POST /api/checklists/{id}/recalculate`, с прогрессом) |
| Новый диалог | «＋ Диалог (JSON)»: файл или вставка в формате API → `POST /api/conversations` (по одной записи) → оценка |
| Экспорт | вкладка «Аналитика»: CSV из браузера (итог, флаги, модель, стоимость, ответ по каждому критерию) и «Экспорт результатов (JSON)» с сервера — `GET /api/export` (константа `EXPORT_PATH` в `api.js`); кнопка неактивна, пока сервер не объявит этот маршрут в `/openapi.json` |

Итог, баллы, ответы, пояснения, модель и стоимость берутся только из ответа сервера. В браузере ничего не пересчитывается.

**Демо-режим.** Если `GET /api/health` не отвечает, страница показывает `demo/demo_data.js` и жёлтый баннер **«ДЕМО-ДАННЫЕ»**. Там 6 синтетических диалогов, не из DEV. Ответы по критериям заданы вручную только для проверки интерфейса, итоги посчитаны `src/cqa/scoring.py` (`python3 web/demo/build_demo.py`). В демо-режиме оценка, апелляции и сохранение чек-листа отключены.

**Пороги отображения** (70 / 90 для раскраски итога, 85 % — целевой уровень по критерию) в задании не заданы. Это настройка («⚙ Пороги отображения» на вкладке аналитики): она только раскрашивает интерфейс и не влияет на баллы.

## Экраны

1. **Мониторинг диалогов.** Список с фильтрами (канал, язык, грубые ошибки, апелляции) и поиском. Транскрипт с номерами реплик `#message_index`. Карточка оценки:
   - итог (если изменён апелляцией, исходный зачёркнут), грубая ошибка, секции;
   - по каждому критерию: ответ, баллы, вес до и после перераспределения N/A, пояснение, правило (`rules`), цитаты-доказательства с переходом к реплике (у звонков ещё и к моменту записи), проверенный участок `checked_range`, причина N/A;
   - модель, стоимость и версия чек-листа.
2. **Апелляции.** Очередь обращений. Проверяющий «Принимает» (новая оценка из вариантов по типу критерия: да/нет, ступени шкалы, N/A) или «Отклоняет»; причина обязательна.
3. **Аналитика.** Средний итог, распределение по порогам (настройка), соблюдение по критериям, экспорт CSV/JSON.
4. **Чек-листы.** Редактор критерия: ID, название, секция, тип, вес, ступени шкалы, N/A и его условие, инструкция, **правила и уточнения (`rules`)**. Правки идут в черновик (хранится в браузере) → «Сохранить версию» → «Применить к диалогам и пересчитать».

## Без сервера

Откройте `web/index.html` двойным кликом — включится демо-режим с жёлтой плашкой «ДЕМО-ДАННЫЕ».

## Запуск у себя

Сайт и сервер в одной ветке: сервер отдаёт `web/` на `http://127.0.0.1:8000/`. Запускайте только локально (`127.0.0.1`), не открывайте сервер в сеть (`--host 0.0.0.0`): по общей сети через него можно запускать оценки на вашем ключе и видеть данные.
